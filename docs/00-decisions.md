## D-001：符号资产全部按标准手绘

| 项 | 内容 |
|---|---|
| 结论 | `assets/gb4728-symbols-kit/` 里的 16 个符号**均为按 GB/T 4728（idt IEC 60617）手绘的 SVG 源码**，版权归本项目所有 |
| 理由 | 手绘 = 可完全掌控几何/栅格/线宽；不依赖任何第三方 CAD 的符号库 |
| 影响 | ① 素材可随项目以 GPL-3.0-or-later 分发；② 图纸与「关于」页保留「符号依据 GB/T 4728 / idt IEC 60617」的出处署名；③ **素材文件只读**，实例样式（选中/hover 颜色）在实例层用 CSS 改，不打补丁 |
| 否决 | 从 KiCad/LTspice 符号库导入：栅格与线宽不可控，且许可证混杂 |

## D-002：前后端架构复制 breadspice 骨架，画布与交互重写

| 项 | 内容 |
|---|---|
| 结论 | 前端 **Vite 5 + Vanilla TypeScript + 原生 SVG**，后端 **Rust axum + JSON-RPC + WebSocket**；直接复制 breadspice 的工程骨架与通信层，**画布渲染与交互逻辑重写** |
| 理由 | breadspice 已验证过同一条技术路线（5.6k 行 TS + 2.7k 行 Rust）；复用它能把风险压在"画布"这一处，而不是同时赌两套架构 |
| 可复制 | `backend/src/server.rs`、`backend/src/protocol.rs` 的骨架、`frontend/src/backend/HttpBackend.ts`、`store/*` 的撤销重做模式、`render/svgAsset.ts` 的 SVG 片段注入 |
| 必须重写 | 画布（自由放置 / 任意角度 / 折线导线）、连通性（导线重合 → 并查集）、网表生成、符号清单驱动、lint |
| 影响 | 两个项目都是 GPL-3，代码复用无许可障碍；但**不要**让两个仓库变成 fork 关系（各自独立演进，需要时手动挑补丁） |

## D-003：画布坐标 = 毫米，引脚与导线都吸附到格点

| 项 | 内容 |
|---|---|
| 结论 | 文档单位 **mm**（1 单位 = 1 mm，与符号 `viewBox` 一致）；栅格 **2.5 mm**；**元件原点、引脚落点、导线折点**全部吸附到 2.5 的整数倍 |
| 理由 | 符号素材的引脚天生落在 2.5 格点上；只要"元件原点 + 导线折点"也吸附，**连接就自动成立**，不需要任何"强行对齐"逻辑 |
| 影响 | ① 缩放只改视图变换，**导出永不缩放**（缩放会以乘法破坏加法建立的栅格关系）；② 旋转/镜像后引脚位置由 `rotate(pin_local) + at` 算出，仍落在格点；③ 关掉吸附时坐标**仍是 mm**，只是不取整 |
| 否决 | 用 px/screen 坐标存文档：分辨率一改就全乱 |

## D-004：布局文件是 JSON 纯文本

| 项 | 内容 |
|---|---|
| 结论 | 原生格式 `.design.json`（UTF-8、LF、缩进 2），内容即 `Document`（见 `docs/03`） |
| 理由 | 可 diff、可 code review、可被脚本处理；与 breadspice 的 `.bread` 是同一思路（它也是 JSON） |
| 影响 | ① 生成物（网表、代码）同样是纯文本，整条链"人能读、git 能比"；② 前端 `JSON.stringify` 的键序必须稳定（写入前排序），否则每次保存都产生大 diff；③ 不存屏幕坐标、不存派生数据（网络名、引脚世界坐标都在导出时算） |

## D-005：**开关不进电路层**，它是插件交互层的"分支选择器"（⚠️ **部分被 D-007 取代**）

| 项 | 内容 |
|---|---|
| 结论 | 开关**不生成任何 SPICE 元件**。开关的本质是**切换插件内部的不同电路分支**；每个分支都是一份**完整独立的电路实现**；**n 个开关 ⇒ 打包 2ⁿ 份完整电路** |
| 理由 | ① 用"理想开关 + 1 mΩ/1 TΩ"模拟拓扑切换在 DSP 里既慢又不稳（矩阵条件数剧变、切换瞬间爆音）；② 每份分支都是完整电路 → 可以各自独立对拍、独立优化，**不存在"半个电路"的中间态**；③ 插件层切换 = 换个 `Circuit` 实现，交叉淡化即可，实现简单且可预测 |
| 谁负责 | **设计器**：只负责"图纸表达 + 变体导出"（同一张图 + 条件元素/条件导线 → 2ⁿ 份网表）；**插件（VST/AU 交互层）**：按参数选择分支 + 交叉淡化 |
| 影响 | ① 设计器**不再生成** `* @rustomp switch` 指令（该指令在 rustomp 侧标记为 legacy/待移除）；② 之前设想的"一个参数驱动多个元件"的生成器扩展**取消**；③ 导出产物从"1 份网表"变成"2ⁿ 份网表 + 1 份组合索引"；④ 分支数上限 **n ≤ 3（8 份）**，超过直接报错（编译时间与内存） |
| 边界 | **true-bypass / 脚踏开关不属于电路分支** —— 那是 `Engine` 的旁通（15 样本对齐 + 5 ms 淡化），图纸里可以画，但不参与分支枚举 |

### D-005 的图纸表达

一张图里放开关符号，用**条件**描述"哪些元素/导线只在该状态存在"：

```jsonc
"switches": [
  { "id": "SW1", "ref": "SW1", "labels": ["非对称", "对称"], "states": ["A", "B"] }
],
"parts": [
  { "ref": "D3", "symbol": "diode", "model": "1N4148", "present": { "SW1": "A" } },  // 只在 A 分支
  { "ref": "R7", "symbol": "resistor", "value": "10k" }                              // 所有分支
],
"wires": [
  { "id": "jw1", "points": [...], "present": { "SW1": "B" } }   // 只在 B 分支：短接 D3
]
```

- **条件元件**（`present`）表达"这个元件装不装"；
- **条件导线**（`present`）表达"这里短接/断开"（导出时等价于合并两个网络 —— 正好复用生成器里
  "≤0.01 Ω 视作导线"的规则）；
- 没有 `present` 的元素出现在**所有**分支里。

## D-007：**本项目不做开关**（"开关不进网表"铁律）

| 项 | 内容 |
|---|---|
| 结论 | 设计器**不提供开关符号**，也**不生成** `branches.json` / 2ⁿ 份网表；D-005 里"设计器负责变体导出"的部分**取消** |
| 理由 | 真实插件的开关本质是**子电路切换**（插件层持有多个 `Circuit`，交叉淡化），不是电路拓扑切换。既然如此，开关就**不属于电路图** —— 画进图里反而会让人以为它会被导出 |
| 谁负责 | 只由**插件项目**处理（`Engine` + 多 `Circuit` + 淡化）。设计器只画"一个分支"的电路 |
| 影响 | ① `docs/06-roadmap` 里 D1 的"分支导出"、D2 的"多组开关"全部删除；② `assets/gb4728-ext/` 不需要补 SPST/SPDT 符号；③ 网表导出始终是**单份** `.cir` |
| 与 D-005 的关系 | D-005 的**前半段仍然成立**（开关不进电路层、n 个开关 ⇒ 2ⁿ 份电路由**插件**维护）；被取消的只是"设计器做变体枚举"这一段 |
| 边界 | 图纸里如果确实需要标注"这台机器有踩钉/拨杆"，用**文字注释**（丝印层）表达，不画电气符号 |

## D-008：「预览」= 生成可保存的截图

| 项 | 内容 |
|---|---|
| 结论 | 工具栏的**预览**按钮打开一个弹窗，里面是**当前画布的位图截图**（PNG），可保存到本地 |
| 理由 | 使用者要的是"把这张图发给别人看 / 贴进文档"，不是再跑一遍仿真（那是**仿真**按钮的事） |
| 实现 | 前端把 `<svg>` 序列化 → `canvas.drawImage` → `toBlob('image/png')`；弹窗内可看、可"下载"；默认按 2× 像素比渲染（清晰度） |
| 不做什么 | 不做"插件面板预览"（那是 box-designer 的职责）；不做 PDF（需要时再加） |
| 三个按钮的分工 | **仿真** = 后端跑 ngspice 出波形；**预览** = 位图截图；**生成网表** = 落盘 `.cir` + lint 报告 |

## D-009：交互以 `prompt.md` 为准（模态编辑，无拖放）

| 项 | 内容 |
|---|---|
| 结论 | 覆盖 `docs/03-editor-model.md` §3 的"拖拽式"交互：**主界面不提供拖放式元件库**，一律模态编辑 |
| 模式 | `esc` 查看 / `r` 电阻 / `c` 电容 / `w` 导线 / `q` 删除 / `m` 移动 / `空格` 元件库 / `d` 复制 |
| 变换 | 放置或手持时 `ctrl+r` 顺时针 90°、`ctrl+e` 左右镜像 |
| 导线 | 只走**上下左右**四个方向；一次点击定一段（两点一线），连续点击继续，`esc` 退出 |
| 删除 | `q` 模式下点元件删元件；点导线只删**该直线段** |
| 移动 | `m` 模式拿起元件，**不影响**与它相连的其他元素；手持时 `esc` 恢复原位 |
| 平移/缩放 | **中键拖拽**平移、**滚轮**缩放（`空格` 已被元件库占用） |
| 移动后的悬空 | 原导线留在原地 → 引脚可能悬空 → **lint 报 warn**（不阻断导出，由用户决定要不要接回去） |
| 不做 | **框选 / 多选**（D1 不做；删除靠 `q` 逐个点） |

## D-011：导线归一化（自动合并重合部分 + 自动接续直导线）

| 项 | 内容 |
|---|---|
| 结论 | 同一水平/垂直直线上的线段，**重叠或首尾相接**就合并成最长的那条；十字交叉**不**合并；零长段丢弃。合并保留最早那条的 `id` |
| 理由 | 用 `w` 连点画出来的直折线会自动变成一条；于是"删除"天然就是"删掉这两个锚点之间的整段" |
| 触发 | 画完一段 / 删完一段 / 载入文件（`normalizeWires()`，纯函数） |
| 边界 | 斜线不合法（D-009），归一化时原样保留，交给 lint 报错 |

## D-012：命中区按几何距离，双击自己检测

| 项 | 内容 |
|---|---|
| 结论 | 命中半径 `tol = 2×栅格 = 5 mm`；元件 = 内缩 25% 的包围盒**或**任一引脚在 `tol` 内；导线 = 点到线段距离 ≤ `tol`；两者都中时**优先导线**（线更细更难命中） |
| 理由 | 细线/小符号用 DOM 命中的话说到底点不中；而且旋转后的符号包围盒会盖住邻居 |
| 双击 | **不用** DOM 的 `dblclick`（每次选中都会重画，节点被换掉后浏览器可能不发），改成自己检测（同目标 + <400 ms） |
| 反馈 | hover 高亮"当前点得中的目标"，让命中区可见 |

## D-013：符号内的文字绑"锚点"，只转锚点不转字形

| 项 | 内容 |
|---|---|
| 结论 | 加载素材时把 `<text>` 转成锚点记录（**viewBox 坐标 = 文字 x/y + 祖先 `<g translate>` 累计偏移**）；渲染时把锚点送进旋转/镜像，字形始终水平 |
| 理由 | 整图旋转会把 `V+/V−`、`C/B/E`、`In/Out` 倒过来；而"只转锚点"既保持位置正确又让字正着 |
| 坑 | 漏掉祖先 `translate` 会让 `origin` 被减两次 → 文字飞到元件本体之外 |
| 边界 | 素材里的 `<text>` 不支持文字级 `transform`（当前 18 个都没有） |

**`node-in` 额外做了水平镜像**（引脚在右侧、朝电路，与 `node-out` 区分），
在 `symbols/overrides.json` 用 `kit_mirror: "x"` 声明，交叉校验先翻转再比对（见 `docs/04 §4.5`）。

## D-015：保存 = 服务端缓存 + 清空历史；启动自动恢复

| 顶栏 | 行为 |
|---|---|
| 命名框 | 直接编辑 `doc.name`；保存/导出的文件名都用它 |
| **保存** | `designer.save` → 写 `$CD_DATA`（默认 `.cache/designs/<名字>.design.json`），并**清空撤销/重做** |
| **导出布局** | 下载 `<名字>.design.json` |
| **导入布局** | 读文件 → 归一化导线 → 名字取自文件 → 清空历史 → 自动 fit |
| 启动 | `designer.last` 恢复上次保存的那份；**指针缺失时取缓存里最新的一份并补指针**（老设计不丢） |

"保存后清空历史"照 breadspice 的语义：保存是**提交点**，之后重做回不到保存前。

## D-016：仿真核心复用 breadspice

| 搬过来 | 说明 |
|---|---|
| `ngspice -b -r result.raw` + `.spiceinit set filetype=ascii` | **ASCII rawfile** 通道（替换 `wrdata`） |
| rawfile 解析 | 复数取模长（AC）、op、容忍被截断的部分结果 |
| 分析类型 | `tran` + `ac`（`op`/`dc` 驱动与解析保留，UI 不开放） |
| 取消 | `designer.stop`（pid + kill，返回部分结果） |
| `fft.rs` | 重采样 → Hann → FFT → 对数频率 + dB |
| `include_str!("assets/models.lib")` | 模型库编进二进制，仿真不依赖启动目录 |

**不做**（用户明确）：op 工作点入口、音频导入、预设音符、播放音频、电流表。
**只画探针曲线**：`.save` 限定 rawfile + 后端白名单过滤 —— 否则 `-r` 会把每个节点电压/电源电流都存下来。

## D-017：仪表挂在元件上

| 元件 | 作用 |
|---|---|
| **IN** | **波形发生器**：幅值/频率在它的属性里设；`tran` 注入 `SIN(amp,freq)`、`ac` 注入 `AC <amp>` |
| **OUT** / **测试点** | **示波器**：双击打开该节点波形 + FFT |

- 仿真弹窗只放"怎么跑"（tran 步长/起始/持续；ac 扫描方式/点数/起止频率）；
- 探针 = **IN + OUT + 所有测试点**，**未放测试点的节点不探**。

## D-020：设计器**不参与 DSP 环节**（只吃布局、只吐网表）

| 项 | 内容 |
|---|---|
| 结论 | 设计器的职责边界是**画图 → `.design.json` / `.cir`**。它不知道、也不关心下游怎么仿真、生成代码、跑 DSP、算 THD |
| 具体表现 | ① 设计器里**不做**"与 rustomp 生成电路的 THD 对拍"面板（对拍留在 rustomp 的 `mc_closed_loop_*` 测试里）；② 设计器的【生成代码】按钮只调用外部工具，把结果**原样显示**，不解释；③ 设计器不引入任何 rustomp 的运行时依赖 |
| 理由 | 一旦设计器开始懂 DSP，它就会被迫跟着求解器/器件模型一起演进（今天是 `newton=`，明天是电荷模型），而它的价值恰恰是"**和下游实现无关的图纸与网表**" |
| 边界情况 | 设计器自己的【仿真】（ngspice）保留 —— 那是"图纸是否画对"的自检，不是下游 DSP 的对拍 |

## D-019：本项目是 rustomp 的**首选**设计器，工程文件可直接进生成器

| 项 | 内容 |
|---|---|
| 结论 | 本项目取代 breadspice 成为 rustomp 生态的**首选**原理图设计器（breadspice 退居次席，仍可用）；它的**一等产物 `.design.json` 直接交给 `rustomp-import`**，不必先导出 `.cir` |
| 理由 | ① 少一步手工导出 = 少一类事故（图改了、忘了重导出）；② 工程文件带着 `.cir` 没有的上下文（端口/测试点/电位器别名），报错时能指名道姓 |
| 怎么保证不漂 | rustomp 侧新增 `CircuitDesigner` 导入器，**运行时读本仓的 `symbols/symbols.json`**（引脚几何的唯一事实来源，不复制一份）；并用本仓导出的 `.cir` 做**逐行对拍**测试 |
| 指令约定（两边必须一致） | `in=`/`out=` 写**节点名**（`IN`/`OUT`）；`param` 的元素名写**网表元件名**（`RP1A`），不写位号（`P1A`） |
| 代价 | 两边多一个“契约变更必须同时改两边文档”的约束：本仓 `docs/05` ↔ rustomp `docs/circuit-import.md` §1/§2/§10 |

> 背景：两种设计器并存时会让人不知道“该用哪个”。定为首选后，breadspice 只在
> “想手搓面包板 / 已有 `.bread` 工程”时还用。

## D-021：连接点黑点 + 「元件脚下导线自动剪掉」

| 项 | 内容 |
|---|---|
| 结论① | 导线与导线的**真实连接**画黑色圆点。判据只有两条：**T 型**（一根线的端点落在另一根线中间）、**3+ 端点重合**。**十字交叉与两线拐角不画点** |
| 结论② | 语法糖：**恰好 2 个引脚**的元件，若两脚落在同一条直导线上、且该导线完整覆盖两脚之间，自动剪掉中间那段（导线正好跨两脚 → 整根删；两头伸出 → 只留两端） |
| 生效时机 | 落元件 / 放下移动 / 每次画完导线 / 载入（恢复、示例、导入）时统一执行；**撤销/重做不剪**（历史必须原样回放） |
| 为什么交叉不画点 | 后端并查集的连通判据是「端点落在导线上」，交叉本身不并网。画点会谎报连接，且与网表不一致 |
| 为什么不剪三脚/多脚元件 | 电位器/三极管/运放的引脚不共线，没有「两脚之间」可言；只对 2 脚符号生效，避免误剪 |
| 代价 | 语法糖只在**编辑期**生效：别的工具直接写出的 `.design.json` 仍可能带短路导线（`rustomp-import` 不做这件清理）。设计器保存的图纸不会 |

## D-022：`d` 复制保留元件属性

| 项 | 内容 |
|---|---|
| 复制什么 | 符号、朝向（`rot`/`mirror`）、`value`、`model`、`alias`、IN 的 `amp`/`freq` |
| 不复制什么 | `id`（新对象）、`ref`（新位号）、`at`（由落点决定） |
| 为什么别名与仪表参数也算 | 电位器别名参与 rustomp 的参数映射；IN 的幅值/频率就是仿真激励。复制一个 0.5 V / 1 kHz 的 IN 却变回默认值，等于静默改了仿真条件 |
| 实现 | `Mode.place` 多一个可选 `attrs: PartAttrs`；`commitPlace` 先铺 `DEFAULTS[symbol]` 再铺 `attrs`；`copyAttrs(src)` 只带真正存在的字段 |
| 边界 | 源元件某字段为空（例如用户清空了数值）→ 不覆盖目标符号的默认值，避免复制出“空值元件” |
