> 每个决策都记"结论 / 理由 / 影响"。**后来的改动不要覆盖旧条目，追加新条目并注明取代关系。**

## D-001：符号资产全部按标准手绘

| 项 | 内容 |
|---|---|
| 结论 | `assets/gb4728-symbols-kit/` 里的 16 个符号**均为按 GB/T 4728（idt IEC 60617）手绘的 SVG 源码**，版权归本项目所有 |
| 理由 | 手绘 = 可完全掌控几何/栅格/线宽；不依赖任何第三方 CAD 的符号库 |
| 影响 | ① 素材可随项目以 GPL-3.0-or-later 分发；② 图纸与「关于」页保留「符号依据 GB/T 4728 / idt IEC 60617」的出处署名；③ **素材文件只读**，实例样式（选中/hover 颜色）在实例层用 CSS 改，不打补丁 |
| 否决 | 从 KiCad/LTspice 符号库导入：栅格与线宽不可控，且许可证混杂 |

## D-002：前后端架构复制 breadspice 骨架，画布与交互重写

| 项 | 内容 |
|---|---|
| 结论 | 前端 **Vite 5 + Vanilla TypeScript + 原生 SVG**，后端 **Rust axum + JSON-RPC + WebSocket**；直接复制 breadspice 的工程骨架与通信层，**画布渲染与交互逻辑重写** |
| 理由 | breadspice 已验证过同一条技术路线（5.6k 行 TS + 2.7k 行 Rust）；复用它能把风险压在"画布"这一处，而不是同时赌两套架构 |
| 可复制 | `backend/src/server.rs`、`backend/src/protocol.rs` 的骨架、`frontend/src/backend/HttpBackend.ts`、`store/*` 的撤销重做模式、`render/svgAsset.ts` 的 SVG 片段注入 |
| 必须重写 | 画布（自由放置 / 任意角度 / 折线导线）、连通性（导线重合 → 并查集）、网表生成、符号清单驱动、lint |
| 影响 | 两个项目都是 GPL-3，代码复用无许可障碍；但**不要**让两个仓库变成 fork 关系（各自独立演进，需要时手动挑补丁） |

## D-003：画布坐标 = 毫米，引脚与导线都吸附到格点

| 项 | 内容 |
|---|---|
| 结论 | 文档单位 **mm**（1 单位 = 1 mm，与符号 `viewBox` 一致）；栅格 **2.5 mm**；**元件原点、引脚落点、导线折点**全部吸附到 2.5 的整数倍 |
| 理由 | 符号素材的引脚天生落在 2.5 格点上；只要"元件原点 + 导线折点"也吸附，**连接就自动成立**，不需要任何"强行对齐"逻辑 |
| 影响 | ① 缩放只改视图变换，**导出永不缩放**（缩放会以乘法破坏加法建立的栅格关系）；② 旋转/镜像后引脚位置由 `rotate(pin_local) + at` 算出，仍落在格点；③ 关掉吸附时坐标**仍是 mm**，只是不取整 |
| 否决 | 用 px/screen 坐标存文档：分辨率一改就全乱 |

## D-004：布局文件是 JSON 纯文本

| 项 | 内容 |
|---|---|
| 结论 | 原生格式 `.design.json`（UTF-8、LF、缩进 2），内容即 `Document`（见 `docs/03`） |
| 理由 | 可 diff、可 code review、可被脚本处理；与 breadspice 的 `.bread` 是同一思路（它也是 JSON） |
| 影响 | ① 生成物（网表、代码）同样是纯文本，整条链"人能读、git 能比"；② 前端 `JSON.stringify` 的键序必须稳定（写入前排序），否则每次保存都产生大 diff；③ 不存屏幕坐标、不存派生数据（网络名、引脚世界坐标都在导出时算） |

## D-005：**开关不进电路层**，它是插件交互层的"分支选择器"

| 项 | 内容 |
|---|---|
| 结论 | 开关**不生成任何 SPICE 元件**。开关的本质是**切换插件内部的不同电路分支**；每个分支都是一份**完整独立的电路实现**；**n 个开关 ⇒ 打包 2ⁿ 份完整电路** |
| 理由 | ① 用"理想开关 + 1 mΩ/1 TΩ"模拟拓扑切换在 DSP 里既慢又不稳（矩阵条件数剧变、切换瞬间爆音）；② 每份分支都是完整电路 → 可以各自独立对拍、独立优化，**不存在"半个电路"的中间态**；③ 插件层切换 = 换个 `Circuit` 实现，交叉淡化即可，实现简单且可预测 |
| 谁负责 | **设计器**：只负责"图纸表达 + 变体导出"（同一张图 + 条件元素/条件导线 → 2ⁿ 份网表）；**插件（VST/AU 交互层）**：按参数选择分支 + 交叉淡化 |
| 影响 | ① 设计器**不再生成** `* @rustomp switch` 指令（该指令在 rustomp 侧标记为 legacy/待移除）；② 之前设想的"一个参数驱动多个元件"的生成器扩展**取消**；③ 导出产物从"1 份网表"变成"2ⁿ 份网表 + 1 份组合索引"；④ 分支数上限 **n ≤ 3（8 份）**，超过直接报错（编译时间与内存） |
| 边界 | **true-bypass / 脚踏开关不属于电路分支** —— 那是 `Engine` 的旁通（15 样本对齐 + 5 ms 淡化），图纸里可以画，但不参与分支枚举 |

### D-005 的图纸表达

一张图里放开关符号，用**条件**描述"哪些元素/导线只在该状态存在"：

```jsonc
"switches": [
  { "id": "SW1", "ref": "SW1", "labels": ["非对称", "对称"], "states": ["A", "B"] }
],
"parts": [
  { "ref": "D3", "symbol": "diode", "model": "1N4148", "present": { "SW1": "A" } },  // 只在 A 分支
  { "ref": "R7", "symbol": "resistor", "value": "10k" }                              // 所有分支
],
"wires": [
  { "id": "jw1", "points": [...], "present": { "SW1": "B" } }   // 只在 B 分支：短接 D3
]
```

- **条件元件**（`present`）表达"这个元件装不装"；
- **条件导线**（`present`）表达"这里短接/断开"（导出时等价于合并两个网络 —— 正好复用生成器里
  "≤0.01 Ω 视作导线"的规则）；
- 没有 `present` 的元素出现在**所有**分支里。

## D-006：电解电容暂不考虑

| 项 | 内容 |
|---|---|
| 结论 | 不新增电解电容（极性电容）符号 |
| 理由 | 当前器件库没有极性电容模型（DSP 侧电容是理想元件，极性只影响耐压/容差，不影响仿真） |
| 影响 | 图纸里用普通电容 + 文字标注 `+`；将来要做时按同一份手册补符号（`assets/gb4728-ext/`），并同步 `symbols.json` |
| 照此处理 | 开关符号**仍然需要**（图纸要画），但它**不生成元件**（D-005）；插孔/DC 座属 P1，等图纸完整性有需求时再补 |

## D-007：**本项目不做开关**（"开关不进网表"铁律）

| 项 | 内容 |
|---|---|
| 结论 | 设计器**不提供开关符号**，也**不生成** `branches.json` / 2ⁿ 份网表；D-005 里"设计器负责变体导出"的部分**取消** |
| 理由 | 真实插件的开关本质是**子电路切换**（插件层持有多个 `Circuit`，交叉淡化），不是电路拓扑切换。既然如此，开关就**不属于电路图** —— 画进图里反而会让人以为它会被导出 |
| 谁负责 | 只由**插件项目**处理（`Engine` + 多 `Circuit` + 淡化）。设计器只画"一个分支"的电路 |
| 影响 | ① `docs/06-roadmap` 里 D1 的"分支导出"、D2 的"多组开关"全部删除；② `assets/gb4728-ext/` 不需要补 SPST/SPDT 符号；③ 网表导出始终是**单份** `.cir` |
| 与 D-005 的关系 | D-005 的**前半段仍然成立**（开关不进电路层、n 个开关 ⇒ 2ⁿ 份电路由**插件**维护）；被取消的只是"设计器做变体枚举"这一段 |
| 边界 | 图纸里如果确实需要标注"这台机器有踩钉/拨杆"，用**文字注释**（丝印层）表达，不画电气符号 |

## D-008：「预览」= 生成可保存的截图

| 项 | 内容 |
|---|---|
| 结论 | 工具栏的**预览**按钮打开一个弹窗，里面是**当前画布的位图截图**（PNG），可保存到本地 |
| 理由 | 使用者要的是"把这张图发给别人看 / 贴进文档"，不是再跑一遍仿真（那是**仿真**按钮的事） |
| 实现 | 前端把 `<svg>` 序列化 → `canvas.drawImage` → `toBlob('image/png')`；弹窗内可看、可"下载"；默认按 2× 像素比渲染（清晰度） |
| 不做什么 | 不做"插件面板预览"（那是 box-designer 的职责）；不做 PDF（需要时再加） |
| 三个按钮的分工 | **仿真** = 后端跑 ngspice 出波形；**预览** = 位图截图；**生成网表** = 落盘 `.cir` + lint 报告 |

## D-009：交互以 `prompt.md` 为准（模态编辑，无拖放）

| 项 | 内容 |
|---|---|
| 结论 | 覆盖 `docs/03-editor-model.md` §3 的"拖拽式"交互：**主界面不提供拖放式元件库**，一律模态编辑 |
| 模式 | `esc` 查看 / `r` 电阻 / `c` 电容 / `w` 导线 / `q` 删除 / `m` 移动 / `空格` 元件库 / `d` 复制 |
| 变换 | 放置或手持时 `ctrl+r` 顺时针 90°、`ctrl+e` 左右镜像 |
| 导线 | 只走**上下左右**四个方向；一次点击定一段（两点一线），连续点击继续，`esc` 退出 |
| 删除 | `q` 模式下点元件删元件；点导线只删**该直线段** |
| 移动 | `m` 模式拿起元件，**不影响**与它相连的其他元素；手持时 `esc` 恢复原位 |
| 平移/缩放 | **中键拖拽**平移、**滚轮**缩放（`空格` 已被元件库占用） |
| 移动后的悬空 | 原导线留在原地 → 引脚可能悬空 → **lint 报 warn**（不阻断导出，由用户决定要不要接回去） |
| 不做 | **框选 / 多选**（D1 不做；删除靠 `q` 逐个点） |
