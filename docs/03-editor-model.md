# 编辑模型与交互

> 目标：**画一张图，就能直接得到可仿真的网表**。
> 所有几何约定都跟符号资产对齐（1 单位 = 1 mm，2.5 mm 栅格）。

---

## 1. 文档模型（前后端共用）

```ts
// frontend/src/types/domain.ts  ↔  backend/src/domain.rs

interface Document {
  version: 1;
  sheet: Sheet;               // 目前只做单页；多页留字段
  parts: PlacedPart[];
  wires: Wire[];
  texts: TextItem[];          // 注释、标题栏补充
  meta: { name: string; author?: string; notes?: string };
}

/** （D-007）本项目不做开关，所以没有 Switch / present 字段 */
interface Switch {
  id: string;
  ref: string;                // SW1
  labels: { zh: string; en?: string };   // "削波模式"
  states: { id: string; label: string }[];  // [{id:"A",label:"非对称"},{id:"B",label:"对称"}]
  /** 每掷的触点对（用于画图与 lint，不参与网表） */
  throws: string[][];         // [[ "1","2" ], [ "2","3" ]]
}

interface Sheet {
  paper: "A4" | "A3" | "A2";
  unit: "mm";                 // 固定；所有坐标都是 mm
  grid: 2.5;                  // 固定；可关吸附但坐标仍是 mm
}

interface PlacedPart {
  id: string;                 // 内部唯一 id（uuid）
  ref: string;                // 参考编号 R1 / C3 / Q2 / U1 / P1 / SW1
  symbol: string;             // symbols.json 的 key（"resistor"…）
  model?: string;             // 器件型号（"1N4148"…），电阻/电容为空
  value?: string;             // "4.7k" / "47n" / "9"
  at: { x: number; y: number };  // 符号原点在画布上的位置（mm）
  rot: 0 | 90 | 180 | 270;
  mirror: "none" | "x" | "y";
  pins: Record<string, Net>;  // ← 可选：仅"命名网络"用；默认空，靠导线推
  fields?: { showValue: boolean; showRef: boolean; showModel: boolean };
}

interface Wire {
  id: string;
  points: { x: number; y: number }[];  // 折点，≥2；坐标吸附到栅格
  net?: string;                        // 显式网络名（可选）
}

type Net = string;            // 网络名（"n$1" 自动 / "IN" 手动）
```

**为什么导线只存折点**：原理图的连通性 = 引脚端点与导线端点的**重合**，
加上导线的折点落在另一根导线上（T 型连接）。这与 LTspice/GB 制图习惯一致，
也让"并查集求网络"变成一次几何遍历（见 §4）。

## 2. 坐标与吸附

| 规则 | 值 |
|---|---|
| 文档单位 | **mm**（与符号 SVG 的 `viewBox` 一致，1 单位 = 1 mm） |
| 栅格 | **2.5 mm**（与符号的引脚跨距一致：两端元件 25 mm = 10 格） |
| 吸附 | 元件原点、导线折点、引脚落点都吸附到 2.5 的整数倍 |
| 缩放 | 视图缩放不改文档坐标（只改变换矩阵），导出永不缩放 |
| 旋转 | 围绕**符号原点**旋转 90°；`mirror` 沿 x/y 轴翻转 |
| 引脚坐标 | `pin_world = rotate_mirror(pin_local) + at` |

> 符号素材"只 translate 不 scale"是硬约束（见资产手册 §4.3）：
> 一旦缩放，引脚就不再落在栅格上。

## 3. 交互（模态编辑 —— 以 `prompt.md` 为准，见 D-009）

**主界面不提供拖放式元件库。** 所有编辑都在"模式"里完成，`esc` 永远回到查看模式。

| 键 | 模式 | 行为 |
|---|---|---|
| `esc` | — | 回查看模式（手持元件时先恢复原位再退出） |
| 双击 | 查看 | 打开属性面板（数值 + 单位 / 型号下拉 / 参考编号 / 别名 / 旋转） |
| `r` | 放置电阻 | 光标变电阻轮廓，左键落一个，**连续放置**直到 `esc` |
| `c` | 放置电容 | 同上 |
| `g` | 放置接地点 | 同上（接地是每个电路的必需品，给单键） |
| `空格` | 元件库 | 弹出全部符号，点一个即进入该类放置模式 |
| `w` | 画导线 | 点一下定第一个锚点 → 往上下左右虚化延伸 → 再点一次定第二点；继续点继续画，直到 `esc` |
| `q` | 删除 | 光标变剪刀：点元件删元件；点导线**删这一整段** |
| `m` | 移动 | 点元件拿起（**不影响相连元素**）→ 再点画布放下；手持时 `esc` 恢复原位 |
| `d` | 复制 | 点一个元件 → 进入"同类放置"；复制完回到粘贴板，可继续点别的元件 |
| `ctrl+r` | 放置/移动中 | 顺时针旋转 90° |
| `ctrl+e` | 放置/移动中 | 左右镜像 |
| `⌘/Ctrl+Z` | 任意 | 撤销 |
| `⌘/Ctrl+Y` | 任意 | 重做 |
| `h` | 任意 | 快捷键手册（顶栏右上角「?」按钮同效） |
| 中键拖拽 | 任意 | 平移视图（`空格` 已被元件库占用） |
| 滚轮 | 任意 | 缩放视图（只改视图变换，**不改坐标**） |

### 3.0 命中区：以鼠标为心的 2×2 格

点细线/小符号太难，所以**判据不是"像素落在图元上"，而是几何距离**：

- 命中半径 `tol = 2 × 栅格 = 5 mm`；
- 元件：内缩 25% 的包围盒（避免旋转后的大空盒子盖住邻居）**或** 任一引脚在 `tol` 内；
- 导线：到线段的垂直距离 ≤ `tol`；
- 两者都命中时，距离接近（<1 mm 差）**优先导线**（线更细、更难点）；
- hover 时高亮"当前点得中的目标"，让命中区可见。

**双击**用自己实现的检测（两次 `pointerdown` 同目标、间隔 <400 ms），
不用 DOM 的 `dblclick` —— 每次选择都会重画，节点被换掉后浏览器可能根本不发 `dblclick`。

### 3.0b 符号里的文字：每个字符标识绑定一个锚点，只旋转锚点、不旋转字形

素材（GB/T 4728）把引脚名写进了 SVG：运放的 `V+`/`V−`、三极管的 `C`/`B`/`E`、
`node-in`/`node-out` 的 `In`/`Out`。整图旋转时这些字会跟着倒过来，所以：

| 步骤 | 做法 |
|---|---|
| ① 加载素材 | 每个 `<text>` 转成**锚点记录** `{锚点坐标, 字号, 对齐, 颜色, 内容}`；图里只留几何 |
| ② 锚点坐标 | 取 **viewBox 坐标** = 文字 `x/y` **加上祖先 `<g transform="translate(…)"` 的累计偏移**（素材里文字坐标是相对那个 `<g>` 的；漏掉这一步字会飞到元件外面去） |
| ③ 渲染位置 | `世界坐标 = toWorld(锚点 − 符号原点, 元件)` —— **只把锚点送进旋转/镜像** |
| ④ 字形 | 文字始终水平（不加 `rotate()`），字号随 `view.scale` 缩放，`text-anchor` 沿用素材 |

一句话：**每个字符标识钉在图内一个固定锚点上，旋转时只给锚点发旋转信号**，字形不参与旋转。
位号（`R1`）与数值（`10k`）也是同一套机制（锚点在符号画布底部或右侧）。

> 素材里的 `<text>` 不支持文字级 `transform`（当前 18 个符号都没有）；将来若有，需先扩展解析。

### 3.0c 数值输入：数字 + 单位

数值类元件（电阻 / 电容 / 电位器 / 电压源）在属性面板里**左边填数字、右边选单位**，
而不是让人自己拼 `10k`：

| 元件 | 默认单位 | 可选 |
|---|---|---|
| 电阻 / 电位器 | `k` | `k`、`Ω` |
| 电容 | `n` | `n`、`p`、`u` |
| 电压源 | `V`（不可选） | — |

存储仍然写成 SPICE 风格（`10k` / `100n` / `4.7u`；`Ω` 与 `V` 不写后缀，如 `470` / `9`），
所以网表不需要改。老文件里不认识的单位（如 `47m`）不会被静默改值 —— 数字保留、单位退回默认。

### 3.1 几条由此推出的规则

1. **移动元件不会拖动导线** → 原导线留在原处，引脚可能悬空 → **lint 报 warn**（不阻断导出）；
2. **导线只走正交方向**（上下左右），斜线不存在 → 网表提取只需要处理水平/竖直线段；
3. 撤销粒度：**一次落点 = 一步**（连续放 10 个电阻 = 10 步）；
4. 不做框选/多选（D-009）——删除用 `q` 逐个点。

## 3.5 开关：本项目不提供（D-007）

图纸上**没有开关符号**，网表导出**永远是单份** `.cir`。

理由：真实插件的开关是**子电路切换**（插件层持有多个完整 `Circuit` + 交叉淡化），
不是电路拓扑切换。把它画进原理图只会让人以为"这里会被导出成一个元件"。

需要标注"这台机器有踩钉/拨杆"时，用**文字注释**表达，不画电气符号。

## 4. 连通性：并查集

```text
1) 建图：每个"引脚端点"、"导线折点"、"导线端点"是一个点
2) union：
   - 同一根导线上的所有点
   - 引脚端点与其所在位置重合的导线点（距离 ≤ 0.01 mm）
   - 导线端点与另一根导线的任意点重合（T 型连接）
3) 每个连通分量 = 一个网络
4) 命名：
   - 有显式网络名（端口符号 / 导线 net 字段）→ 用它（重名即同一网络，短路检查）
   - 否则自动命名 n1 / n2 …（按最小坐标排序，保证确定性）
5) 接地符号（earth）→ 网络名固定为 "0"
```


**为什么不"编辑时实时合并节点"**：
面包板那样边拖边并会引入大量中间状态，撤销重做会变得很脏。
原理图更适合"**几何即真相**，网表在导出时算"——这也方便"画到一半先看看网表"。

## 5. 参考编号与自动命名

| 类型 | 前缀 | 允许的型号（闭集，来自 rustomp 器件库） |
|---|---|---|
| 电阻 | `R` | —（值必填） |
| 电容 | `C` | —（值必填） |
| 电位器 | `P` | —（总阻值必填） |
| 二极管 | `D` | `1N4148` `1N34A` `1N4007` `1N5817` |

## 6. 撤销/重做

命令式（与 breadspice 一致）：

```ts
type Command =
  | { kind: "addPart"; part: PlacedPart }
  | { kind: "movePart"; id: string; from: XY; to: XY }
  | { kind: "setField"; id: string; field: keyof PlacedPart; from: unknown; to: unknown }
  | { kind: "addWire"; wire: Wire }
  | { kind: "moveWirePoint"; id: string; index: number; from: XY; to: XY }
  | { kind: "delete"; parts: string[]; wires: string[] }
  | { kind: "batch"; commands: Command[] };   // 例如"拖动 3 个元件"
```

- 每个命令实现 `apply()` / `revert()`
- 连续拖拽**合并成一条**（用拖拽开始时的快照）
- 属性面板的输入做 300 ms 合并
- 文档变更后标脏 → 自动持久化（localStorage）+ 提示保存 `.design.json`

## 7. 文件格式

| 文件 | 内容 | 用途 |
|---|---|---|
| `*.design.json` | `Document`（§1） | **编辑器的原生格式**，可版本化、可 diff |
| `<name>.cir` | SPICE 网表 + `* @rustomp` 指令（**单份**，D-007） | 交给 `rustomp-import`；也可被 ngspice 直接仿真 |
| `<name>.png` | 预览截图（D-008） | 存档 / 发给别人 |
| `*.svg` | 图纸导出（栅格 + 符号 + 标注） | 打印/分享 |
| `*.netlist.json` | 网表的结构化形式（元件/网络/端口） | 调试、其它工具消费 |

> 四种产物都由**同一份 `Document`** 导出，避免"图、网表、代码"三份真相。

## 7.5 命名 / 保存 / 导出 / 导入（照 breadspice 的语义）

| 顶栏 | 行为 |
|---|---|
| **命名框** | 直接编辑 `doc.name`；保存与导出的文件名都用它 |
| **保存** | `designer.save` → 写服务端缓存（`$CD_DATA`，默认 `<repo>/.cache/designs/<名字>.design.json`），**并清空撤销/重做** |
| **导出布局** | 下载 `<名字>.design.json` 到本地 |
| **导入布局** | 读本地 `.design.json` → 替换文档 → 归一化导线 → 名字取文件里的 `name`（没有就用文件名）→ **清空历史** → 自动 fit |

**启动自动恢复**：打开页面时先调 `designer.last`（后端读缓存里"上次保存"的那一份）→ 恢复文档、名字、导线归一化、清空历史、自动 fit；
后端没起或缓存为空时安静回退到首屏演示。`?load=<name>` 仍可显式载入示例，`?fresh=1` 强制跳过恢复。

> 指针文件缺失时（功能上线前保存的设计）会自动**取缓存里最新的一份**并补上指针 —— 老设计不会丢。

"保存后清空历史"是 breadspice 的既有语义：保存是一个**提交点**，
之后重做回不到保存之前的状态，避免"重做把已保存的内容改掉"这种反直觉行为。

文件名只做最小白名单清洗（去 `/ \ : * ? " < > |` 等），超过 80 字符截断，空名字回退「未命名电路」。

## 8. 导线归一化（自动合并 / 自动接续）

**规则**：同一条直线上的线段（水平 y 相同 / 垂直 x 相同）只要**重叠或首尾相接**，
就合并成一条最长的线段；合并保留最早那条的 `id`（撤销、选中、diff 都稳定）。

| 场景 | 结果 |
|---|---|
| `(0,0)–(10,0)` + `(10,0)–(20,0)` | 一条 `(0,0)–(20,0)` |
| `(0,0)–(20,0)` + `(5,0)–(30,0)` | 一条 `(0,0)–(30,0)` |
| `(0,0)–(20,0)` + 竖线 `(10,-10)–(10,10)` | **两条**（十字交叉不合并；连通性由并查集算） |
| `(0,0)–(20,0)` + `(10,0)–(10,0)`（零长） | 丢弃零长段 |

由此得到两个使用性质：

1. **`w` 模式里连点画出的直折线会自动变成一条**，不需要"画完再整理"；
2. **删除 = 删掉这两个锚点之间的整段**（因为合并后一根线就是一段最大的直线）。

触发时机：画完一段、删完一段、载入设计文件/示例时各跑一次（`normalizeWires()`，纯函数）。
斜线不属于合法输出（D-009），归一化时原样保留，交给 lint 报错。
