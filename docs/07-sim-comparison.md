# 仿真能力对照：breadspice vs 本设计器

> 目的：**看清楚哪些该抄、哪些不该抄**。
> breadspice 是"面包板仿真器"（仿真即主功能）；本设计器是"原理图 → 网表 → rustomp 电路"，
> 仿真只是验证手段之一（另一条是生成代码 + THD 对拍）。所以不求功能对齐，只求**够用且不误导**。

---

## 1. breadspice 的仿真是怎么做的

| 层 | 实现 |
|---|---|
| **分析类型** | `op` / `dc` / `ac` / `tran`（`AnalysisKind`；op、dc 前端入口隐藏，后端代码保留） |
| **参数** | 「仿真选项」弹窗按类型切换字段：`dc`(源/起止/步长)、`ac`(dec·oct·lin/点数/起止频率)、`tran`(步长/起始/持续) |
| **驱动** | 子进程 `ngspice -b -r result.raw circuit.cir`；同目录写 `.spiceinit` → `set filetype=ascii`，强制 **ASCII rawfile** |
| **成功判据** | **rawfile 能否解析**（ngspice 对没有 `.print/.plot/.fourier` 的 tran 会以非零码退出，但结果已经写好了） |
| **取消** | 记录子进程 pid，`stop_running()` 直接 kill；返回 `cancelled: true` + **部分结果** |
| **结果结构** | `op`: 节点 → 电压 map；`traces`: `[{name, x[], y[]}]`（AC 的复数取幅值） |
| **模型库** | `assets/models.lib` 用 `include_str!` **编进二进制**，网表生成时把 `.MODEL`/`.SUBCKT` 注入 → 网表自包含 |
| **激励** | 面包板元件自带源/仪表；另外**可上传音频**（ffmpeg → PCM → PWL）当电压源，内置 5 个预设音符（C/A/G/E/D，44.1 kHz/16-bit） |
| **前端呈现** | 「电压表」弹窗（op 或 tran 末帧读数）、「示波器」弹窗（SVG polyline + **FFT** + **播放** + **下载 WAV**） |
| **频谱** | `fft.rs`：非均匀重采样 → Hann 窗 → FFT → 对数频率轴 + dB，去直流避免泄漏 |

---

## 2. 本设计器现在有什么

| 项 | 现状 |
|---|---|
| 分析类型 | **只有 tran**（正弦激励），参数：幅值 / 频率 / 时长 |
| 步长 | 自动 = `时长/3000`，不暴露 |
| 激励 | 图纸没画源时，自动在 `in` 网挂 `SIN(0 amp freq 0 0 0)`；`VCC/VEE` 自动补 `DC ±9` |
| 探针 | **固定** `v(IN)` / `v(OUT)`（端口） |
| 驱动 | `ngspice -b` + `.control … wrdata` → 解析 4 列文本 |
| 成功判据 | 退出码 0 且 wrdata 文件存在 |
| 结果 | `{t, vin, vout}`，降采样到 ≤2000 点；另算 **THD**（前 9 次谐波最小二乘投影 + Hann 窗） |
| 呈现 | 弹窗里一张内联 SVG 波形（in 虚线 / out 实线，自动缩放、ms 横轴、零线、图例） |
| 模型库 | `assets/models.lib`（14 型号取自 rustomp；2N7000 用 LEVEL=1 近似；OP07A 最小宏模型），**运行时读文件**后内联 |
| 取消 | 无 |
| 音频 | 无 |

## 3. 差异清单

| # | 能力 | breadspice | 本设计器 | 值不值得补 |
|---|---|---|---|---|
| 1 | op（静态工作点） | 有（UI 隐藏） | 无 | **值得**：晶体管偏置对不对，一跑就知道；`.op` 成本极低 |
| 2 | ac（频响） | 有 | 无 | **值得**：滤波/增益级的转折频率、相位，是原理图设计最常问的问题 |
| 3 | dc（扫描） | 有（UI 隐藏） | 无 | 可以后补（转移特性曲线） |
| 4 | tran 参数 | 步长 / 起始 / 持续 | 只有时长（步长自动） | **值得**给高级参数（默认值保持现状） |
| 5 | 结果读取 | ASCII **rawfile**（多变量/复数/op 统一） | `wrdata`（手写 4 列解析） | **值得换**：rawfile 是通用通道，op/ac 都靠它 |
| 6 | 取消长仿真 | 有（kill + 部分结果） | 无 | 值得（高 Q 电路/慢瞬态容易卡住） |
| 7 | 频谱 | 完整 FFT（对数轴 dB） | 只有 THD 数值 | **THD 保留**，再加频谱图（能看杂散/次谐波） |
| 8 | 音频激励 | 上传音频 + 5 个预设音符 | 只有正弦 | 对"吉他效果器"其实很有价值（用真实演奏驱动），但优先级中 |
| 9 | 播放 / WAV 导出 | 有 | 无 | 低（我们要听效果去插件里听） |
| 10 | 多曲线 / 任选探针 | 点元件看电压表、示波器取任意网络 | 固定 in/out | 值得（至少允许选 1–2 个额外探针） |
| 11 | 仪表呈现 | 独立「电压表」「示波器」窗口 | 单个波形弹窗 | 我们的够用（不需要仿真空面包板的手感） |
| 12 | 模型库来源 | `include_str!` 编进二进制 | 运行时读 `assets/models.lib` | **顺手改**：编进二进制，避免"从哪个目录启动"影响仿真 |
| 13 | 相位/阻抗 | AC 复数取幅值（丢弃相位） | — | 跟 breadspice 保持一致的取舍即可 |

---

## 4. 结论与建议

**该抄的三件（按性价比）**

1. **把结果通道换成 ASCII rawfile**：op / dc / ac / tran 全走同一条路，`wrdata` 的 4 列特例就可以删掉；
2. **补 `op` 与 `ac`**：原理图设计最常问的两件事（偏置对不对、转折频率对不对）；
3. **`models.lib` 用 `include_str!`**（一行改动）：仿真不再依赖当前工作目录。

**值得考虑的两件**

4. tran 的**步长/起始**放开为高级参数（默认值不变，避免"能跑但结果糊"）；
5. 频谱图（在现有 THD 旁边加一个"看频谱"按钮）。

**不必抄的**

- 上传音频/预设音符/播放/下载 WAV：那是"用面包板当效果器听"的玩法，我们的听感验收在插件里做；
- 独立电压表/示波器窗口：我们的单弹窗已经够用，多了反而分散。

> 一句话：**breadspice 的仿真围绕"玩"，我们的仿真围绕"查"** ——
> 所以缺的是"能查得更准"的东西（op/ac/rawfile/探针），而不是"能听得更爽"的东西。
