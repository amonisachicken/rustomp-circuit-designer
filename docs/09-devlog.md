## E1 先把符号清单钉死（`63d164c`）

`tools/gen-symbols.py`：解析素材顶部注释（名称/标准/画布/引脚画布坐标）+ `<g translate>` 原点，
**与 kit 的 `build/make-symbols.py` 的 PINS 表交叉校验**，再用手写的 `symbols/overrides.json`
把"局部坐标 → 引脚名"绑上，产出 `symbols/symbols.json`（入库 + `--check` 防漂移）。

**为什么值得先做**：引脚坐标错了，画图时看起来完全正常（引脚就在线上，只是差 0.5 mm），
网表却会多出孤立节点。这一步立刻抓到了文档里预告过的坑：
运放素材注释的引脚顺序是 `(IN+)(IN-)(OUT)(V+)(V-)`，而 rustomp 约定是 `IN+ IN- V+ V- OUT` ——
所以 `pinOrder` 必须独立于素材顺序。

## E2 D0：模态编辑骨架（`63d164c`）

零运行时依赖（Vite + TS，只有两个 devDeps）：`model / symbols / render / mode / main` 五个模块。
`mode.ts` 是纯状态机（`查看 / r / c / w / q / m / 空格 / d`），`render.ts` 只负责把文档画成 SVG。

第一个能跑的样子：放电阻、放电容、画正交导线、删除、移动、复制、撤销重做。

## E3 网表导出 + lint（`01f69d5`）

后端 `netlist.rs`：并查集求网络（导线端点、T 型接点、引脚落在导线上）、
引脚按 `pinOrder` 取名、自动网络名按"网络最小坐标"排序保证**确定性字节**、
电位器展开、MOS 衬底接源极、lint 6 条（无地/重复编号/型号闭集/缺型号/悬空/缺端口）。

用一张分压图做**黄金文件测试**。随后验证了一件大事：

```text
设计器产出 .cir → cargo run -p rustomp-import -- x.cir --mna x.rs
→ 成功生成 Ckt（3 个未知量，节点 IN/OUT）
```

**M-B 里程碑的雏形当场成立。**

## E4 仿真（`2bd8465` → 后来整体换成 breadspice，见 E10）

第一版是 `wrdata` 取 4 列自己解析，只有 tran、固定 in/out 探针。
跑低通时踩到"只看全程最大值会被起始瞬态骗"的坑：

| | 值 |
|---|---|
| 全程最大值比 | 0.255（假） |
| 只看窗口最后 25% | **0.157**（= 理论 `1/√(1+(f/fc)²)`） |

教训：**瞬态分析的判据必须取稳态段**。

## E5 交互返工：命中区与双击（`15e033e`）

用户实测反馈三条：插孔/电源座没意义、双击打不开属性、细线点不中。

- 删掉 `jack` / `dc-jack` 两个符号（**18 个**），并修了 `sync-symbols` 不清旧文件的坑；
- **双击**不用 DOM 的 `dblclick`：每次选择都会重画，两次点击落在不同节点上，浏览器可能根本不发 ——
  改成自己检测（同目标 + <400 ms）；
- **命中区**从"像素落在图元上"改成几何距离：元件 = 内缩 25% 的包围盒**或**任一引脚在 `tol=5 mm` 内；
  导线 = 点到线段的距离 ≤ `tol`；两者都中时优先导线。

> 中途发现"只用包围盒"会让竖放的电容（15×30 mm 的盒子）吃掉旁边 4 mm 处的导线 ——
> 所以加了"引脚距离"这一路。

## E6 导线归一化（`b696f72`）

同一水平/垂直直线上的线段，**重叠或首尾相接**就合并成最长的一条（保留最早的 `id`，撤销/选中稳定）；
十字交叉不合并；零长段丢弃。于是"用 `w` 连点画出来的直折线"自动变成一条，
**删除就是删掉这两个锚点之间的整段**。

## E7 符号里的文字必须与图形解耦（`39ecd83` → `452b041`）

素材把引脚名写在 SVG 里（`V+/V−`、`C/B/E`、`In/Out`），整图旋转时文字会倒过来。
做法：加载时把每个 `<text>` 转成**锚点记录**，渲染时把锚点送进旋转、字形保持水平。

**第一次实现把锚点算错了**：素材里 `<text x/y>` 是相对 `<g transform="translate(cx,cy)">` 的局部坐标，
我直接拿它减符号原点 → `origin` 被减了两次 → 文字飞到元件外面（用户一眼看出来）。

| | 文字原始 | 错误结果 | 正确 |
|---|---|---|---|
| NPN 的 `C` | (3.6, −10.8) | (−11.4, −28.3) | (3.6, −10.8) |

修法：加载时维护 `<g>` 栈，**累计祖先 translate** 转成 viewBox 坐标，渲染时再减原点。

## E8 一组小改进（`6bda094` / `d66e438`）

- 重做改 `⌘/Ctrl+Y`；
- 数值输入 = **数字框 + 单位下拉**（电阻 kΩ/Ω、电容 nF/pF/µF、电压源固定 V）；
  存储仍是 `10k` / `100n` / `9`，网表不用改；不认识的旧后缀（`47m`）不会被静默改值；
- `g` 放接地点、`h` 快捷键帮助、顶栏加 `?`；
- **IN 节点镜像**（引脚朝右对着电路，与 OUT 区分）：素材改了，kit 的 PINS 表保持原稿，
  在 `overrides.json` 用 `kit_mirror: "x"` 声明"这是有意镜像"，交叉校验先翻转再比对；
- 电位器按 **50% 抽头**写标称值（`max=500k` → 两段 `250k`）。

**IN 镜像连带的坑**：模板里 IN 的位置要跟着改，否则
① 符号压在运放上；② 导线从无关引脚上穿过 → 后端把"引脚落在导线上"判为相连 → **凭空短路**
（`C1 IN IN 47n`）。所以模板生成器加了**避让布线**：两条 L 形路线都试，选不穿过无关引脚的那条。

## E9 保存/导出/导入 + 启动自动恢复（`487ece6` → `c7e9f95`）

照 breadspice 的语义：**保存** = 写服务端缓存（`.cache/designs/<名字>.design.json`）+ **清空撤销/重做**；
**导出布局** = 下载；**导入布局** = 读文件 + 清空历史 + 自动 fit；顶栏加**命名框**。

启动时调 `designer.last` 自动恢复上次保存的布局。

> 这里救回了一份真实设计：缓存里有用户的 `pretty-face.design.json`（24 元件 / 30 导线，
> 两只 AC127 的锗管法兹），但它保存于我加"指针"之前 → 指针对不上。
> 于是加了回退：**指针缺失时取缓存里最新的一份，并把指针补上** —— 老设计不会丢。

## E10 仿真核心整体复用 breadspice（`62a261e`）

按用户"避免重复劳动"的要求，把 breadspice 的仿真主体搬了过来（两边同为 GPL-3、同作者）：

| 搬过来 | 说明 |
|---|---|
| `ngspice -b -r result.raw` + `.spiceinit set filetype=ascii` | ASCII **rawfile** 通道，替换掉 `wrdata` |
| rawfile 解析 | 支持复数（AC 取模长）、op、被截断的部分结果 |
| 分析类型 | `tran` + **`ac`**（`op`/`dc` 的驱动与解析保留，UI 不开放） |
| 取消 | pid + kill，返回部分结果（`designer.stop`） |
| `fft.rs` | 重采样 → Hann → FFT → 对数频率 + dB（`designer.fft`） |
| `include_str!` 模型库 | 仿真不再依赖"从哪个目录启动" |

**去掉**（用户明确不要）：op 工作点入口、音频导入、预设音符、播放音频、电流表。

拼网表时踩的两个坑：

1. **`.ends` ≠ `.end`**：想用字符串替换插 `.print`，结果把模型库里的 `.ends OP07A` 也切了 →
   ngspice 报 `.end.print`。改成在拼网表时一次生成探针行；
2. **`ngspice -r` 默认保存所有变量**（每个节点电压 + 每个电压源电流）→ 图上混进 `i(vsim)`。
   加 `.save v(in) v(out) v(tp…)` 限制 rawfile，并在后端再按探针名白名单过滤。

## E11 仪表挂到元件上（`4563c13` → `eb47d5e`）

按用户的要求把"仪表"从独立窗口改成元件自带：

| 元件 | 作用 |
|---|---|
| **IN** | **波形发生器**：幅值/频率在它的属性里设（仿真弹窗只留时间/频率范围） |
| **OUT** / **测试点** | **示波器**：双击打开该节点波形 + FFT |

探针只包含 **IN + OUT + 所有测试点**，未放测试点的节点不画。
界面文案也清了一遍：标题「仿真」、折叠区「日志」，不再出现 `rawfile`/`breadspice` 这类实现细节。

## E12 与 rustomp 主项目的对接（2026-10-27 晚）

**背景**：设计器已经是 rustomp 生态里的**首选**原理图设计器（breadspice 退居次席），
所以两边要真对上，而不是"各自看起来都能跑"。

对接是怎么落地的（细节在 rustomp 仓库 `crates/rustomp-import/src/designer.rs`、
`docs/circuit-import.md` §1/§2/§10）：

| 方向 | 内容 |
|---|---|
| **产物直读** | rustomp-import 新增 `CircuitDesigner` 导入器：直接吃 `.design.json`（不用先导出 `.cir`） |
| **几何一致性** | 导入器运行时读**本仓库的** `symbols/symbols.json`（引脚坐标 = 唯一事实来源），不复制一份几何 |
| **对拍** | 用本仓库导出的 `.cir` 当裁判：读工程文件得到的网表必须与它**逐行相同** |
| **指令修正** | `param` 里必须写**网表元件名**（`RP1A`/`RP1B`），不能写位号（`P1A`）——原来写位号，rustomp 侧找不到元件，电位器参数被静默丢弃 |

**`in=` 的语义对齐**：设计器导出的网表是"纯拓扑"（激励由 DSP 每拍注入），
所以 `in=IN` 指的是**节点**，不是激励源。rustomp 侧原来只认元件名，于是这类图
退化成"无输入端口（纯直流电路）"，生成的 `Ckt` 会**直接忽略输入**。现在两种写法都认。

对接时在 rustomp 侧抓到两个求解器 bug（与本设计器无关，但只有真跑设计器产物才会暴露）：

1. **固定电位节点的值没写回解向量**：电源轨/输入节点的槽位永远是 0，
   电容历史与非线性器件的线性化点都读到了 0 → 瞬态发散；
2. **线性外推热启动在陡沿处会把人送进沟里**：固定次数的牛顿从一个远离解的点出发 → 发散；
   现在跳变超过 10% 就退回上一拍解（稳态仍外推，性能不变）。

还有一处**本仓**的坑（E12 修）：【生成代码】优先用 `rustomp/target/{release,debug}/rustomp-import`
这个预编译二进制 —— 如果 rustomp 那边改了源码却没重新 build，按钮会静静拿到旧版产的代码
（实测：`in=` 语义改了以后，界面里生成的 `Ckt` 仍写着“无输入端口”）。
现在先比 mtime：rustomp-import 的源码/清单比二进制新，就直接走 `cargo run`。

> **曾有一个已知问题，已修好**：用户自己保存的 `pretty-face`（两极锗管 AC127 法兹）在 ngspice 里正常，
> 但在 rustomp 的实时路径上会在第 78 个样本发散。真因不在本设计器，在 rustomp 的器件模型：
> ① `exp` 用 `min(80)` 硬截断把**导数钉成 0**（锗管 `Is=5µA` 的正常工作点就在截断区附近）；
> ② 实时路径的"3 次迭代"是硬天花板，没收敛的解被留给下一拍。
> 修好后该电路的 `.op` 与 ngspice **一位不差**（0.1005 / 0.1749 / 7.6499 …）。
> 细节见 rustomp `DEVLOG.md` E81。

## E13 M-C 闭环成立：设计器工程 → 生成代码 → THD 与 ngspice 一致（2026-10-27 晚）

M-C 的定义（`docs/06-roadmap.md`）：**生成的 `Ckt` 的 THD 与设计器自己的仿真一致**。

rustomp 侧把 E85 之后的能力用起来了：设计器工程 → `rustomp-import --mna` → `Ckt`，
喂 1 kHz 正弦（192 kHz 内层速率），取最后 20 ms；ngspice 拿**同一张导出的网表**
（+`VSIM` 激励 +`devices.lib`）跑同样的窗口；两边用同一个 `rustomp-oracle::thd_percent`。

| 电路 | 性质 | 我们的 `Ckt` | ngspice | 差 |
|---|---|---|---|---|
| `lowpass`（10k + 100n） | 线性对照（守尺子） | 0.0000 % | 0.0000 % | 0 |
| `diode-clip`（1N4148 ∥ 1N34A） | 二极管硬削波 | 26.554 % | 26.554 % | **−0.000 pp** |
| `pretty-face`（AC127 ×2 法兹） | 锗管 + 反馈 + 削波 | 60.53 % | 60.93 % | **−0.39 pp** |

顺带把 `diode-clip` 的三件套（`.design.json` + `.cir` + 生成物）入库，于是这个例子同时吃三条守卫：
**工程文件 → 网表**逐行对拍、**工程 → 生成物**漂移守卫、**生成物 → THD** 对拍。

> 锗管那 0.39 pp 是模型缺口（`Nk`、`Xcjc/Cjcs`、`Irb`），不是链路问题；
> 二极管纯电路已经能对齐到显示精度。

# 2026-10-28：连接点黑点 + 元件脚下导线自动剪裁

用户提的两个改进，都是"画图时少犯一类错"：

1. **导线与导线的连接点用黑色圆点标识** —— 否则 T 型接点和十字交叉在屏幕上长得一样，
   而它们在后端是**完全相反**的语义（T 型并网、交叉不并网）；
2. **语法糖：两脚元件落在同一直导线上时，自动剪掉两脚之间残存的导线** ——
   否则"先拉一根长线再把电阻插上去"会留下把元件短路的一截线，网表里 R 被旁路，
   画面上却完全看不出来。

```text
15:25  27 项浏览器自测全绿 + 纯函数 node 断言 10 条
```

## E14 连接点黑点：判据必须和并查集一致

**做法**：`model.ts` 新增 `wireJunctions(wires)`，从几何现算（不存进文档，老文件不需要迁移）：

| 情形 | 画点？ | 原因 |
|---|---|---|
| 一根线的端点落在另一根线**中间**（T 型） | ✅ | 后端并查集会把它们并成一个网络 |
| 三根及以上线的端点重合 | ✅ | 真正的分支点 |
| 两根线端点相接（拐角） | ❌ | 制图惯例；`normalizeWires` 也常把它们合成一条 |
| 两根线十字交叉（都在各自中间） | ❌ | **交叉不并网**，画点会谎报连接 |

渲染在导线之后、元件之前（`.junctions circle { fill:#0f172a }`），半径 `1.2 mm × scale`
（下限 2.5 px），与 1.6 px 的线宽比例稳定；缩放时点跟着缩放，但不被线宽吃掉。

**为什么不标"引脚落在导线上"**：那是元件引脚，符号自己的端点已经画出来了；
用户这次要的是**导线 vs 导线**的区分。

## E15 语法糖：只在"完整覆盖两脚"时剪

**做法**：`model.ts` 的 `trimWireBetweenPins(doc, pa, pb)`：

1. 两脚必须共线（水平或垂直）；
2. 只处理**完整覆盖 `[p_lo, p_hi]`** 的导线 —— 两头都够得着才算"元件躺在线上"；
3. 剪成 `head = [w.lo, p_lo]` 与 `tail = [p_hi, w.hi]`，长度 0 的丢掉；
4. 保留原导线 id（选中/撤销稳定），剪出来的另一端用新 id；`Wire.net` 两边都继承。

**只对恰好 2 个引脚的符号生效**（`trimWiresUnderParts` 里 `sym.pins.length !== 2` 直接跳过）：
电位器 3 脚、三极管/运放多脚，引脚不共线，没有"两脚之间"可言，误剪风险大于收益。

**四个生效时机**，都收在同一个撤销步里：

| 时机 | 为什么 |
|---|---|
| `commitPlace` | 先画线、后放电阻 |
| `dropAt`（移动落下） | 把电阻拖到一根长线上 |
| `commitWire`（每次画完一段线） | 先放电阻、后拉线穿过它 |
| 载入（恢复/示例/导入 `.design.json`） | 修老图纸里的历史短路；保存后的文件从此干净 |

**撤销/重做故意不剪**：历史快照必须原样回放，否则"撤销"会变成一个会改文档的操作。

# 2026-10-28（续）：`d` 复制带上数值与型号

## E16 复制不该“复制个形状”

**现象**：`d` 只带了符号、旋转、镜像，属性走了 `DEFAULTS` —— 复制 `1N34A` 得到 `1N4148`，
复制 `4.7k` 得到 `10k`。两个元件在画布上一样，网表和声音不一样。

**做法**：给 `Mode.place` 加一个可选 `attrs: PartAttrs`
（`value` / `model` / `alias` / `amp` / `freq`），`commitPlace` 的展开顺序变成：

```ts
...DEFAULTS[m.symbol],   // 1) 目标符号的默认值
...m.attrs,              // 2) 复制带来的属性覆盖
```

`copyAttrs(src)` 只把**真正存在**的字段放进 `attrs`（`undefined` 不写入），
所以“用户清空数值后复制”不会把空值盖到默认值上。位号仍走 `nextRef`，位置由落点决定。

**为什么连 `alias` / `amp` / `freq` 一起带**：电位器别名是 rustomp 参数映射的一部分
（`param RP1A ... `），IN 的幅值/频率是仿真激励。只带 value/model 会留下一半“看起来复制了、
实际没复制”的坑。

## 踩坑：自测里的双击检测把复制吃掉了

第一版自测 `copy-value=false` 而 `copy-model=true`，很迷惑。原因不在复制逻辑，而在
**双击检测**：上一项 `view-drag-pan` 刚点过同一个电阻，间隔 < 400 ms；
`d` 之后的第一下点击被当成“双击开属性”，复制根本没落到 place 模式，
`doc.parts.at(-1)` 拿到的是旧元件（默认 10k）。第二次复制点的是二极管（不同 id），所以通过了。

修法：复制自测前 `await 450 ms`，让双击窗口过期。**教训**：用真实事件驱动自测时，
“上一步的点击”是隐式状态，时间窗口类逻辑（双击、长按）必须显式错开。

# 2026-10-28（再续）：剪线语法糖扩展到多脚器件

## E17 多脚器件也有共线引脚

D-021 第一版只在 `sym.pins.length === 2` 时生效，理由写的是“多脚器件的引脚不共线”。
这句话是错的 —— 把 `symbols.json` 摊开就能看到：

| 器件 | 共线引脚 | 世界坐标（`rot=0`，`at=(0,0)`） |
|---|---|---|
| 二极管 / 电阻 / 电容 / 电压源 | 两脚 | 水平/垂直 |
| **电位器** | 1 – 3 | `y=0`，`x=±12.5`（滑臂在 `y=-12.5`，不参与） |
| **BJT（npn/pnp）** | C – E | `x=2.5`，`y=∓12.5` |
| **JFET** | D – S | `x=2.5`，`y=∓12.5` |
| **MOSFET** | D – S | `x=5`，`y=∓12.5` |
| **运放** | IN+ – IN−（`x=-15`，`y=∓5`）、V+ – V−（`x=0`，`y=∓12.5`） | 见左 |

一根导线从 C 拉到 E、从 D 拉到 S、或横跨电位器 1–3，同样是**把器件短路**。
“先拉一根长线再把器件放上去”的操作习惯对所有器件都存在，没有理由只保护两脚元件。

**做法**：`trimWiresUnderParts` 不再看引脚数量，改为：

1. 把器件的引脚按 `y`（水平线）与 `x`（垂直线）分组；
2. 每组 ≥ 2 只引脚才处理（单脚/不共线的组直接跳过）；
3. 取该组**最外两脚**，交给原来的 `trimWireBetweenPins`（仍需导线完整覆盖这段）；
4. 同一条线只剪一次（`Set` 记账），避免同一段被重复切割；
5. 旋转/镜像后按 `toWorld` 的世界坐标分组，因此 `rot=90` 的器件同样成立。

**为什么取“最外两脚”而不是所有相邻对**：引脚在同一根线上的器件（如运放 V+ / V−）
本应整段不与导线共存；剪掉最外两脚之间就把它们全断开了。若分多次剪相邻对，
中间会留下悬空的短线段，反而制造新的垃圾。

**为什么不会误伤现成图纸**：条件仍是“导线**完整覆盖**两脚之间”。示例电路的导线都终止在引脚上，
不会横跨同一器件的两只脚 —— 用编译出的 `mode.ts` 对 4 个示例做了回归，全部 `wires` 数量与
几何逐字节不变（`same` ×4）。

# 2026-10-28（修 bug）：从 T 型交点继续画，黑点消失

## E18 根因不在画点，在归一化吃掉了端点

**现象**：T 型接点（竖线端点在横线中间）有黑点；从交点继续往下画一笔变成十字，黑点没了。

第一反应是 `wireJunctions()` 的判据漏了情况，但它没漏 —— 它判"端点落在另一根线上"和
"≥3 端点重合"。真正被破坏的是**几何**：

```text
画之前： H: (0,0)-(20,0)      V1: (10,0)-(10,-10)
         交点 P=(10,0) 是 V1 的端点、H 的内部  → T 型接点 ✓

继续画： V2: (10,0)-(10,10)  → normalizeWires 把 V1+V2 合并成 (10,-10)-(10,10)
         此时 P 是 H 的内部、也是 V 的内部     → 交叉 ≠ 连接 ✗
```

而且这**不只是显示问题**：后端 `netlist.rs` 的并查集同样只认「端点落在另一根线上」，
所以网表里那两根线真的断了。视觉上的黑点消失只是同一故障的可见症状。

**修法**（D-023）：在 `normalizeWires()` 合并同向线段之前，先算「禁越点」：

- 禁越点 = 某根导线的端点落在**另一根不同方向**导线的中间（就是 T 型接点）；
- 每一步合并比较合并后的区间：如果某个禁越点在输入里是端点、合并后会变成内部点，
  就**跳过这次合并**，让两根短导线各自保留自己的端点。

**为什么不去改画点判据**：让 `wireJunctions()` 猜"这个十字其实以前是 T"是猜不出来的；
把连接证据（端点）保留下来，判据就能继续只看几何，文档里也不用存 junction 标记。

**边界都试过**：

| 情况 | 结果 |
|---|---|
| 直导线首尾相接 / 重叠 | 照旧合并（没有禁越点） |
| 拐角后再接一条同向线 | 照旧合并（拐角是端点对端点，不是端点落在中间） |
| 先画长竖线，再从交点向左右各画一笔 | 两个水平半段**不合并**，交点保留 |
| 在交点同侧继续延长（多段同向） | 只在禁越点处断开，其余照旧接续 |
| 连续 normalize 两次 | 结果逐字节一致（幂等，不会每次增生） |
| 删掉造成禁越的垂直导线 | 两个同向半段恢复合并（禁越点消失） |
| 4 个示例电路 | 载入 + 剪裁后几何全部不变（`same` ×4） |

代价是交点处多保留一根短导线 —— 相对"连接悄悄断掉"完全值得。

## E19 修复预览截图：内联 CSS 后再交给浏览器光栅化（2026-10-29）

**现象**：工具栏「预览」生成的 PNG 不正确（线条/文字缺失或成块），但画布本身显示正常。

**真因**（三条叠加）：

1. 预览把 `<svg>` 克隆后序列化成**独立的 SVG 图片**；页面 `style.css` 的 class 规则不会跟过去
   （`.wires line` / `.parts text` 等全部失效），浏览器按 SVG 默认值画 → 黑块/丢线；
2. 克隆保留了 `id="canvas"`，`#canvas` 的 CSS（`width/height/background`）会反过来干扰这张图片；
3. 之前先把 `w×h` 的 SVG 光栅化，再 `drawImage` 放大到 2×，即使内容对了也发糊。

**修法**（不写自定义渲染器、不引 html2canvas）：

- 克隆**当前视野**的 SVG，去掉 `id`/`style`，移除 `.grid`、`.pins`、`.ghost`、`.dangling`、
  `line.preview` 等临时层，去掉 `.hovered`；
- 把 `document.styleSheets` 里能读到的规则**内联成 `<style>`**（跨域样式表 `try/catch` 跳过）；
- 设 `viewBox="0 0 w h"`，`width/height = 2w/2h`，让浏览器**原生按 2× 光栅化**；
- 背景 `<rect>` 放在图形之下；`Image` 加载 → `canvas.drawImage` → `toBlob("image/png")`；
- 失败时在状态栏显示原因，不再静默。

**验证**：

| 项 | 结果 |
|---|---|
| `npm run typecheck` / `npm run build` | 通过 |
| Chromium headless（CDP）打开 `?load=diode-clip` → 点预览 | 弹窗出现，图片 **2400×1118**（1200×559 视野 @2×） |
| 像素统计 | 非白像素 54,936、颜色分桶 52（不是空白/纯黑） |
